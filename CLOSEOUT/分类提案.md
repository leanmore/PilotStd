## 一、为什么不整体搬家

现有 `docs/` 已经是按用途分的（onboarding / reference / adr / governance / testing / debt / records / plans / guides / architecture），缺的不是目录，而是**入口与去重**。而路径被以下位置硬编码：

| 依赖点 | 内容 |
|---|---|
| `AGENTS.md §7.1` | 17 行“触发条件 → 必须读取的文档”路径表 |
| `docs/index.md` | 13 份必读入口，逐条写死 `docs/...` 路径 |
| `docs/DOCUMENTATION_MAP.md` | 117 篇全量目录 |
| `G-031` 文档联动 / `G-032` 文档健康度 / `G-037` 触发对齐 | 三个门禁脚本按路径扫描 |
| `tests/test_check_module_doc_mappings.py`、`tests/test_docs_drift.py` | 测试按路径断言文档与模块映射 |

一旦把 `docs/reference/` 改名成 `docs/20-开发指南/`，上述 4 道门禁 + 30 余处链接会同时断。收尾阶段做这件事，收益是“好看”，代价是“门禁红 + 链接修一周”，不划算。

**因此本提案的分层是“知识域映射”，不是“目录搬迁”。** 老板若要物理重组，见 §六备选方案与代价。
