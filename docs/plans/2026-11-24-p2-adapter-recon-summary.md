## 2. 最重要的共性发现：**「注册了但不可达」是系统性风险**

三份侦查**独立**指向同一类缺陷——适配器配置齐备，但路由永远选不中：

| 实证 | 修复前 | 修复后 |
|---|---|---|
| `T/CIESC 001-2019` | `['njbz365']` | `['ttbz']` |
| `NB/T 47016-2023` | `['gongbiaoku','hbba',…]` | `['energy']` |
| `HJ/T`/`TB/T`/`YD/T`/`DZ/T`/`JT/T` | 全部落 L2 兜底 | 命中各自特色站 |
| `DB50/T 950-2026` | `['dbba']`（**若 cqis 声明 `[DB50]` 将永不命中**） | —（待决策，见 §4） |

**已修**（`64a6a2f2`）：`T/` 识别、`NB/T` 领域回退、`_type_matches` 声明优先/基码回退。
**未修（需决策）**：`DB50`/`DB35` 这类**省份粒度**——`_extract_std_type` 统一产出 `DB`，
站点若声明 `DB50` 则永不命中；要么声明 `DB`+L2 兜底（零改动），要么给 v2 加省份粒度（+0.25–0.5 人日）。

> **纪律**：以后新增任何适配器，落地前必须跑一次 `get_route_chain(<真实样本号>)` 证明它能被选中，
> 并写进该适配器的测试。否则就是「注册了但不可达」，健康探针还会误报 found（探针直连适配器、不经路由）。

## 3. 实施顺序（按依赖拓扑，不按站点列举顺序）

```
批次 A（零依赖，先做）
  A1 重庆 cqis 适配器（VIABLE，真实 API 已取证）—— ✅ **已完成** df6f6a7c
      └ 路由方案：采用「零改动」，声明 DB 与 dbba 同属 L1（dbba 在前）；省份精准粒度仍待决（§4-①）
  A2 API Webstore 适配器（VIABLE，证据最全）
      └ 口径确认：检索为 POST（只读检索，见 §4-②）

批次 B（依赖已就绪）
  B1 ASME 适配器 —— 依赖 P1 G1/G2（`ASME B16.5` 拆号）**已合入 `9e884765`**，可排
      └ 第一步：designator 归一化表（`Section VIII Div.1 → BPVC.VIII.1`）+ 单测
  B2 现有适配器补齐（ttbz 的 P0 5 项 / energy 的 3 项）
      └ 其中 ttbz 的「路由不可达」已由 `64a6a2f2` 修复，其余为 fixture/分页/replaces

批次 C（冻结）
  C1 福建 —— BLOCKED，待站点网络开放后复测（复测前置，不排开发）
```

**为什么先 A1/A2 而不是先补现有**：A 批是**新增数据源**（业务收益），B2 是存量质量；两者文件不重叠，
若人手允许可 A1/A2 与 B2 并行；但 A 批含「路由可达性验证」这一新纪律，先做可把流程跑顺。

## 4. 需要先拍板的 2 个决策

| # | 决策 | 选项 | 影响 |
