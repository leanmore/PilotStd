# A-28 阶段二方案（并发安全版，待确认，未动代码）

## 0. 并发安全：user_id 必须作为参数贯穿，禁止改单例属性

**采用 A：显式参数**。

- 新增读函数：`enabled_for(user_id)`、`is_quiet_hours(user_id)`；
- **禁止**在请求处理中写 `manager._user_id = user_id` 再调用（manager 是进程单例，
  并发 A/B 请求会互相覆盖，把"无隔离"变成"偶发串号"）；
- 现有事件发送路径仍使用构造时绑定的 `_user_id`（单用户兼容），
  真正的多用户事件隔离需"每次调用传上下文"，不在本阶段；
- 迁移完成后，API 读配置一律走带 `user_id` 的函数；manager 属性只保留兼容。

## 1. 读路径

| 路径 | 改法 |
|---|---|
| `manager.enabled` | 保留（绑定 `_user_id`，兼容事件路径）；新增 `enabled_for(user_id)` |
| `_dispatcher.send_event` | 系统关判断保持**最前**（`_dispatcher.py:87` 早退）；阶段二改为 `enabled_for(host._user_id)`，语义不变 |
| `manager._enabled` | **系统级总开关 AND 用户偏好**：`cfg_enabled and pref_enabled(默认 True)` |
| 静音 `_suppression_queue.is_quiet_hours` | 新增 `is_quiet_hours(user_id)`：偏好优先 → config 回退；解析失败记 warning 并回退 config |
| `get_logs` 用户过滤 | 不在阶段二（无 `user_id` 列，需 A-21） |
| 规则 | policy 已用户级，不改 |

## 2. 五个补充

### 2.1 静音偏好解析失败

偏好 JSON 损坏/类型不对 → `logger.warning`（结构化上下文）+ **回退 config**；
不允许因一条坏偏好让静音判断抛异常。

### 2.2 迁移写入 vs "从未设置"

阶段一把 config 值写入了所有用户偏好，存储上分不清"迁移值"与"用户显式设置"。
阶段二**接受该限制**并在文档写明；后续可在偏好值内加 `source: "migrated"|"user"`
（不阻塞本阶段）。

### 2.3 系统关短路顺序

必须 **系统关 → 直接返回**，在静音判断之前：
- 现状 `send_event` 在 `_dispatcher.py:87` 先判 `_enabled` 早退，`do_send` 的静音在 `:202`；
- 阶段二保持该顺序，并补测试：系统关 + 静音窗口 → **不写队列、不补发**。

### 2.4 `/notification/test` 豁免

现状是**天然豁免**：`do_test_send` 直接取渠道并 `ch.send()`，不经过
`send_event`/`_enabled`（`docker/api/notification.py:48` 注释亦明确）。
阶段二保持现状，并补一条回归：系统关时 `/test` 仍 `ok:true`；
若未来 `/test` 改走 `do_send`，必须显式加豁免标志。

### 2.5 多用户"并存读"测试

至少 1 例：同一 DB 同时存在 user1/user2 偏好（不同值），
**不切换全局状态**，分别调用 `enabled_for(1)` / `enabled_for(2)` / `is_quiet_hours(1/2)`，
断言各自正确——这才叫隔离；"切两次分别读"不算。

## 3. 兼容与回滚

- 读顺序：偏好 → config 回退；双读保留一版；
- 写路径：UI 继续双写；`scope_migrated` 只表示数据已搬；
- 回滚：删偏好行 + 恢复 config 备份。

## 4. 验收

- 单用户行为不变（迁移前后同值）；
- 双用户并存读 / 系统关优先 / 静音坏偏好回退 / `/test` 豁免；
- 全量 + 部署后设置页一致性；
- 完成后 T-42；A-6/D-14 等阶段二部署稳定后再跑基线。

## 5. 三个确认 + 三项补充（2026-10-30 定稿）

### 5.1 事件路径用组合值

`send_event` 的早退改为 `enabled_for(host._user_id)`，即**系统 AND 用户**组合值：
用户关自己 → 不收事件。注意 `host._user_id` 是 manager 构造时绑定的单例值，
**多用户下事件发送仍不隔离**（已知限制，记 A-35，留 A-21 解决）。

### 5.2 系统关时队列里已有的消息

`release_suppressed` 补一层：**先查系统开关**。
- 系统关 → 本轮跳过，消息**保留在队列**（不删，避免丢数据）；
- 系统开 → 下个 tick 正常补发。
新增测试：静音入队 → 关系统 → release 不发送；再开系统 → 补发。

### 5.3 `/test-event` 的豁免

现状 `_do_send` 直接进 `_dispatcher.do_send`，**不判 `_enabled`**，所以系统关时它仍会发/入队——
这是链路绕过，不是有意豁免。
**决定：`/test-event` 不豁免**。阶段二在端点显式检查 `enabled_for(user_id)`：
系统关 → 返回 `ok:false`（提示通知已关闭）；`/test` 保持天然豁免（`ch.send()` 直达）。
测试锁定两条行为。

### 5.4 `user_id=None`

`enabled_for(None)` → **纯系统值**（只读 `notification.enabled`）；
`is_quiet_hours(None)` → 只读 config（不查偏好）。调用方无需自行判空。

### 5.5 回滚与"偏好已被用户改动"

新增 `--rollback`：
- 以迁移时的偏好快照为基准；
- 未改动 → 删除迁移写入的偏好行；
- 已改动 → **先导出当前偏好到备份**，再删除/保留（保留为默认，删除需显式 `--force`）；
- 恢复 config 备份（config 原键仍在，通常只需删标记）。

### 5.6 事件路径限制入账

新增 debt **A-35**：事件发送路径仍绑定单例 `_user_id`，多用户串号；真正隔离需每次调用传上下文，属 A-21 后续。

## 6. 两处确认 + 三处实现注意（2026-10-31 定稿）

### 6.1 `/test-event` 选 B：测试完整链路，系统关时拦截

- 系统关 → `/test-event` 返回 `ok:false`（提示通知已关闭），**不豁免**；
- 文档/响应写明：这是预期行为；只测渠道通信用 `/test`；
- 与 A-23 初衷一致：它验的就是完整链路（含静音）。

### 6.2 系统长期关闭时队列堆积

现状（代码核实）：`notification_queue` **没有容量上限、没有过期、补发没有速率限制**；
`release` 只按 `scheduled_time <= now` 取数。
阶段二补：
- **过期机制**：默认 72 小时，`notification.queue_expire_hours` 可配；release 前把超期
  `suppressed` 标记为 `expired` 并记日志“过期丢弃 N 条”；
- **补发上限**：每 tick 最多 100 条（可配），避免重开瞬间刷屏；
- 排队期间系统关 → 本轮 release 跳过（消息保留，等过期或系统重开）。

### 6.3 实现注意

1. “默认 True”用 `pref.get("enabled", True)`，**不要** `or` / `None` 短路；
   补测试：偏好无 `enabled` 字段 + 系统开 → 有效。
2. 回滚明确两步：`--rollback` 先导出当前偏好到
   `backups/a28_rollback_<时间戳>/preferences.json`，**再**删偏好行 + 恢复 config；
   用户改动有据可查。
3. 三命令区分：
   - `--reset`：删标记，数据不动（改归属清单后用）；
   - `--force`：强制重跑（上次部分失败用）；
   - `--rollback`：导出偏好 + 删偏好行 + 恢复 config（撤回迁移状态）。
