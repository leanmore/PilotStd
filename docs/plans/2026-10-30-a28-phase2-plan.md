# A-28 阶段二方案：读路径切换（待确认，未动代码）

## 1. 要改的读路径

| 路径 | 现状 | 改法 |
|---|---|---|
| `manager._enabled` | 偏好覆盖 config | **系统级总开关 AND 用户偏好**：`cfg_enabled and pref_enabled(默认 True)`；系统关时常规事件全停，手动测试仍走 `/notification/test` 不受影响 |
| 静音判定（`_suppression_queue`） | 读 `notification.quiet_hours_*` | **偏好优先**（`notification_quiet_hours` JSON）→ 无偏好回退 config；时区/边界逻辑不变 |
| `get_logs` 用户过滤 | 无 `user_id` 列 | **不在阶段二做**：需 A-21 加列/迁移后才有过滤依据；阶段二只保证配置读路径 |
| 事件规则 | policy 已用户级 | 不改（已符合分层） |

## 2. 兼容双读

- 读顺序：用户偏好 → config 回退；一个版本内保留双读；
- 写路径：UI 继续双写（偏好 + API），迁移标记 `scope_migrated` 只表示"数据已搬"，不改变读顺序；
- 回滚：删除偏好行 + 恢复 config 备份即可回到旧行为。

## 3. 回归

- **单用户行为不变**：迁移前后同一 config 值，`_enabled`/quiet 结果一致；
- **两用户隔离**：临时 DB 造 user1/user2，偏好不同 → 同一 manager 上下文分别读各自值（需把 `_user_id` 注入读函数）；
- 系统关 + 用户开 → 仍关；系统开 + 用户关 → 关；系统开 + 无偏好 → 开。

## 4. 验收

- 3 类测试（单用户不变 / 双用户隔离 / 系统关优先）；
- 全量 + 部署后手动：设置页显示与服务端一致；
- 完成后 T-42 再开始；A-6/D-14 等阶段二部署稳定后再跑基线。
