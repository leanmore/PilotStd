# A-27 P1 方案：菜单架构层 + 企微（供确认，未写代码）

## 1. 菜单模型（渠道无关）

```json
{
  "channel": "wecom",
  "items": [
    {"key": "menu.today", "label": "今日公告", "type": "click", "action": "query_today"},
    {"key": "menu.tools", "label": "工具", "type": "group", "children": [
      {"key": "menu.scan", "label": "手动扫描", "type": "click", "action": "run_scan"},
      {"key": "menu.logs", "label": "查看日志", "type": "view", "url": "/notification-logs"}
    ]}
  ]
}
```

- `type`：`click`（动作）/ `view`（URL）/ `group`（一级分组）；
- 约束：一级 ≤3、每组二级 ≤5；`key` 全局唯一（渠道内）；
- 静态（渠道级），不按用户。

## 2. 存储

- 先 `config/menus.json`（`{channel: [items]}`），不做管理页；
- 读取：启动/`menu sync` 时校验（层级、数量、key 唯一、action 白名单）；
- 后续可加 DB/管理页，不改模型。

## 3. Action 白名单

```python
MENU_ACTIONS = {
    "query_today": QueryTodayAction,   # 查询今日公告（只读）
    "run_scan": RunScanAction,         # 触发扫描（异步、限频 1 分钟 1 次）
    "open_logs": UrlAction("/notification-logs"),
}
```

- 复用 `callback_service` 的动作执行/幂等出口；
- 未知 action/键 → 忽略并记日志（不执行）。

## 4. 企微 CRUD 封装

- `WeComMenuClient`：`create/get/delete`（`cgi-bin/menu/*`，用 `access_token`，`agentid`）；
- 去抖 + 每日次数保护（额度以官方为准）；失败回滚到上一版菜单（先 get 再 create）；
- 测试：mock HTTP，断言 URL/body/agentid、错误码映射。
