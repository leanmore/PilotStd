## A-28 通知配置权威源（合并项目）

**为什么合并**：原 A-28（`enabled`）与原 A-29（`rules`）是同一原则的两个实例。若一个选"偏好赢"、一个选"policy 赢"，会出现两套冲突规则，维护者无法判断。**原则只能有一个**。

### 选项

| 选项 | 规则 | 迁移 | 回滚 | 成本 |
|---|---|---|---|---|
| **A 偏好赢**（现状） | 用户偏好覆盖 config | 把 config 存量值一次性写入偏好（迁移脚本） | 从迁移前备份恢复偏好表 | 小 |
| **B config 赢** | config 覆盖偏好 | 把偏好存量值写入 config；删除偏好读取 | 恢复 config 备份 + 代码回退 | 小—中 |
| **C 分层** | **系统级**：渠道凭证、全局开关；**用户级**：订阅规则、静音时段。冲突时**用户级优先**，但系统级"总开关"可强制关闭 | 需新增 `scope` 标记 + 两张表/字段；存量配置逐项归类 | 需按 scope 反向迁移 | **大（高于 A/B）** |

**选 C 时必须先定**：
1. 哪些算系统级（渠道凭证、总开关、回调密钥） vs 用户级（订阅规则、静音、通知偏好）；
2. UI 放哪（系统级在管理页，用户级在设置页）；
3. 冲突规则（用户级优先，但系统级总开关可一票关闭）。

### 迁移与回滚（通用）

1. **迁移前备份**：`data/config.json` + 复制 `user_preferences` 相关行（导出 JSON）；
2. 迁移脚本幂等（按 key 存在则跳过），带 `--dry-run` 打印将改行；
3. 回滚：恢复备份文件/行 + 回退代码；**不删旧数据**（保留双写一个版本）。
