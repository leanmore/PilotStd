| 10 | `callback_data` | `str` | `""` | TEXT NOT NULL DEFAULT ''（**纯字符串，不做 JSON 编解码**） | — | 64 |
| 11 | `attachments` | `list[AttachmentSpec]` | `field(default_factory=list)` | **TEXT**（JSON 数组文本；同上） | ★ | 64 |
| 12 | `channel_message_ids` | `dict[str, str]` | `field(default_factory=dict)` | **TEXT**（JSON 对象文本） | ★ | 64 |

**4 个非标量字段的列类型统一为 `TEXT`**，理由（三批同款，已写入各迁移文件注释与 `core.md`）：
① 本仓非标量落库一律 `TEXT` + `json.dumps/loads`（`notification_queue.event_data`、
`user_preferences.preference_value`），可复用同一编解码模块；
② SQLite 的 JSON1 扩展（`json_extract` 等）在旧库/精简构建上**不保证存在**，不依赖它；
③ 这 4 列只整存整取、**不做 SQL 层查询**（阶段 3 的回调按 `message_id` 反查，用的是 1a 已建的**独立列**，
不是 JSON 内部字段）。

**新增数据类型（`pilotstd/core/notification/specs.py`）**：`ActionSpec` / `AttachmentSpec`（均
`@dataclass(frozen=True)`）+ 闭集词表 `ACTIONS`（6 个动作）/ `ACTION_STYLES` / `ATTACHMENT_KINDS`
+ `specs_to_jsonable()`。`ActionSpec.__hash__` **手写**（`frozen` 不阻止自动 `__hash__` 去哈希
不可变的 `args`，会抛 `TypeError`）。

## 四、4 个非标量字段全走 `_json_codec`（断言证明）

| 字段 | 落库侧 | 读回侧 | 证明用例 |
|------|-------|-------|---------|
| `task_context` | `_json_codec.dumps` | `_json_codec.loads_dict` | `stage1b::test_task_columns_written`（`json.loads(列值) == 原值`） |
| `channel_message_ids` | `_json_codec.dumps` | `_json_codec.loads_dict` | `stage1c::test_channel_message_ids_stored_as_json_object` + `test_codec_is_the_only_conversion_path` |
| `actions` | `specs_to_jsonable` → `_json_codec.dumps` | `_json_codec.loads_list` | `stage1c::test_actions_attachments_stored_as_json_text` + `test_codec_is_the_only_conversion_path` |
| `attachments` | 同上 | `_json_codec.loads_list` | 同上 |

**最直接的判据**是 `stage1c::test_codec_is_the_only_conversion_path`：它断言 4 列的落库值**逐一等于**
`_json_codec.dumps(…)` 的产出——若有人绕过编解码把原值直接送进 INSERT（如 `msg.actions` 是 `list`），
比较对象类型不同（`list` vs `str`）即失败。

**补充**：非标量字段**不进** `_QUEUE_MESSAGE_FIELDS` 标量白名单（否则 `NotificationMessage(**fields)`
会收到 JSON 字符串），由 `stage1b::test_scalar_fields_in_whitelist_context_not` 与
`stage1c::test_whitelist_contains_only_scalar` 双向锁定。
