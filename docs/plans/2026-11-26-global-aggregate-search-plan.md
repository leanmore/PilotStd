# 全局聚合搜索技术方案与排期评估（2026-11-26）

> 目标（参考 MoviePilot 体验）：用户输入**一个关键词/标准号**，系统在 24 个已接入站点上**并行检索、合并去重、按置信度排序**，
> 一次返回「哪些站点有、状态如何、可去哪个站点看详情/下载」，而不是逐站手动查。

## 1. 现状盘点（事实）

| 维度 | 现状 | 文件 |
|---|---|---|
| 站点能力模型 | **24 个站点**声明（supported_types / industries / is_international / search_reliability）；可靠性分布：`unknown 20 / medium 4` | `config/site_capabilities.yaml` |
| 适配器 | **27 个**适配器模块（含细分站） | `pilotstd/query/adapters/` |
| 意图解析 → 路由 | 已实现：类型/领域解析、`L1 精准 → L2 综合兜底 → L3 探索`、决策可观测（`RouteChain.decisions`） | `pilotstd/query/routing/router_v2.py` |
| 检索策略 | 精确优先 + 关键词/模糊回退（`search_strategy.py` 376 行）；按站配额、日配额 | `search_strategy.py`、`daily_quota.py` |
| 网络层 | 超时 + 重试 + 会话复用（`network.py` 203 行，含 `Lock` 与 `sleep` 退避） | `network.py` |
| 熔断/轮换 | 适配器熔断（`adapter.circuit_breaker.*` 可配）+ UA/来源轮换 | `adapter.py`、`rotator.py` |
| 缓存 | 查询结果缓存（TTL） | `cache.py` |
| 健康探测 | 适配器健康探测 | `health_probe.py` |

**核心缺口**：以上能力都是**单站点内**的；缺少「跨站聚合编排层」——一次查询只走路由链逐个尝试，没有并行、合并去重、跨站置信度排序与聚合 UI。

## 2. 模糊搜索支持度评估

| 站点类型 | 代表站点 | 标准号精确 | 关键词模糊 | 备注 |
|---|---|---|---|---|
| 国标/综合 | `std_gov` / `csres` / `cssn` / `gongbiaoku` / `ahbz` | ✅ | ✅（关键词回退） | 作为主力覆盖 GB/行标 |
| 国际特色 | `api_webstore` / `asme` / `iso_gov` | ✅ | ⚠️ 仅标准号/系列词 | Coveo/POST 检索，模糊支持弱 |
| 地方标准 | `dbba`（全国地标库）/ `cqis`（重庆，全文） | ✅ | ✅ | dbba 覆盖全国 DB，cqis 补重庆全文 |
| 行业站 | `miit` / `jtst` / `mee` / `nrsis` / `sppt*` / `tdpress` / `ncha` / `energy` / `ccsn` | ✅ | ⚠️ 各站差异大（需逐站验证矩阵） | 部分站点仅支持精确号 |
| 团体标准 | `ttbz` | ✅ | ⚠️ 依赖组织名 | |

**结论**：标准号查询可全站并行；**纯关键词模糊**需按站分组降级（精确优先 → 关键词 → 仅国标/综合站兜底），
并在 UI 上标注「来源站 + 置信度」（精确命中=高，关键词/模糊=中）。

## 3. 并发防封方案

| 层 | 方案 | 参数建议 |
|---|---|---|
| 全局并发闸门 | 线程池/协程池 + `Semaphore`，限制同时在途站点数 | 默认 4~6（可配 `query.aggregate.max_concurrency`） |
| 每站令牌桶 | 复用 `daily_quota` + `site_capabilities.constraints.batch_limit`；单站 QPS 上限 | 1~2 QPS/站 |
| 退避与限流码 | 429/5xx 指数退避 + `Retry-After`（已有 `parse_retry_after`）；单站连续失败触发**熔断**（复用现有 circuit_breaker） | 3 次失败 → 熔断 5 分钟 |
| 请求指纹 | 轮换 User-Agent（`rotator.py`）、Session 复用 keep-alive、按站设置 `Referer/Origin`；预留代理池接口（`query.proxy_pool`） | — |
| 失败隔离 | 单站失败/超时**不影响整体**：返回部分结果 + `errors[]` 标注；超时预算总 8s（单站 4s） | — |
| 缓存优先 | 相同查询 5 分钟内命中 `cache.py` 直接返回（免请求） | TTL 300s |
| 观测 | 聚合请求记录各站耗时/命中/失败（扩展 `query_metrics`），作为后续调参依据 | — |

## 4. UI 交互设计

1. **统一搜索框**（现有页头部）：支持标准号/关键词；输入防抖 350ms，Enter 立即；
2. **结果卡片**：标准号（加粗）+ 名称 + 状态徽标（复用 `stdStatus` 语义色）+ **来源站** + 置信度徽标（精确/关键词）；
3. **分站聚合视图**：默认「去重合并列表」（同标准号多站合并为一行，展开显示各站来源与链接）；可切换「按站点分组」；
4. **渐进加载**：「国标/综合」首屏先出（快），行业/地标站点结果到达后追加（骨架屏占位，复用 `AppLoading`）；
5. **失败可见**：某站失败时在结果底部显示「N 个站点暂不可用（点击重试）」，不谎报为空；
6. **动作**：收藏/下载/查看详情沿用现有按钮与权限模型（管理端 vs 用户端一致）。

## 5. 排期评估（3 批，估 4-5 人日）

| 批次 | 内容 | 估时 | 关键验收 |
|---|---|---|---|

## 6. 风险与前置

- **风险 1**：各站关键词语义差异大 → 需先输出「站点×查询类型」支持度矩阵（P0 内做 3 站抽样）；
- **风险 2**：并发放大被封风险 → 默认并发 4、单站 1-2 QPS，灰度观察一周再调；
- **风险 3**：结果去重的标准号归一（`GB/T 1.1-2020` vs `GB/T1.1—2020`）→ 复用 `parse_std_number` 归一；
- **前置**：先在 P0 中把「聚合查询」做成**只读、可开关**（`query.aggregate.enabled`，默认关），不影响现有单站查询链路。
