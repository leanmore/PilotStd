# A-28 通知配置权威源：开关清单（供确认，未改代码）

> 决策 C（分层）已定。动代码前需逐项确认下表归属。

| 开关 | 当前存哪 | 建议归属 | 冲突规则 |
|---|---|---|---|
| 通知总开关 `notification.enabled` | config + 偏好（双写，偏好优先） | **系统级主开关** | 系统关 → 全部静默；系统开时用户可关自己的投递 |
| 渠道启用/禁用 | `user_credentials`（按用户） | **用户级**（个人渠道开关）；"允许使用哪些渠道"另设**系统级**白名单 | 系统未允许的渠道，用户不能启用 |
| 渠道凭证（bot_token/webhook/secret） | `user_credentials`（按用户） | **用户级**（模型预留 `scope` 字段；未来多用户可升级为“系统级默认凭证 + 用户可选覆盖”） | 用户只能改自己的凭证；系统默认凭证被用户覆盖时以用户为准 |
| 回调密钥/URL（企微 Token/AESKey） | config（全局） | **系统级** | 仅管理员可改 |
| 事件订阅/规则 | DB `notification_policy`（按用户） | **用户级** | 用户级覆盖默认规则 |
| 静音时段 | 当前 config（全局） | **用户级**（A-21 目标） | 用户级优先；系统级主开关可一票关闭 |
| 通知偏好（主题/语言等） | `user_preferences` | 用户级 | — |

## 已知系统级键（迁移白名单）

即使旧配置未标 `scope`，以下键一律归**系统级**，防止迁移误归用户：

- `notification.enabled`（总开关）
- `notification.callback.*`（回调 URL/Token/AESKey）
- 渠道全局白名单（允许使用的渠道）

其余键默认 `user`。

## 冲突语义（需你确认）

**系统级总开关关闭 = 常规事件投递停止；手动测试发送不受影响**（用户显式触发，用于验证配置）。
理由：用户配通知时常先关系统开关试配置、再手动测试；全停会导致无法验证。
（若改为“一刀切全停”，需明确：关了就任何东西都发不出，测试前必须先开。）

## 迁移 + 回滚（若选 C）

1. **备份**：`data/config.json` 复制；导出 `user_preferences`、`notification_policy` 涉及行；
2. **加 scope**：配置项增加 `scope` 元数据（system/user）；无 scope 的旧键默认 user；
3. **迁移**：系统级键（总开关、回调密钥）保留在 config；用户级键（静音、规则）从 config 复制到用户偏好/policy，再停止读 config；
4. **幂等 + dry-run**：脚本按 key 存在跳转，`--dry-run` 打印将写行；
5. **回滚**：恢复备份文件/行 + 代码回退；**不删旧数据**（保留一个版本双读）。
