# 方向 C 深度扫描（第四轮，2026-11-25）：i18n / 时区 / 边界

> 新口径：**i18n 键完整性（前后端）、时区处理、边界与空值、幂等写入**。
> 核心工具事实：`pilotstd.i18n.t()`/`_()` 缺键时**返回键名本身**（fail-loud），
> 因此「代码用了词典没有的键」= 用户界面/通知里出现原始 key —— 这是本轮最大发现面。

## 2. 本轮修复

### 2.1 前端：`SettingsView.vue` 两个 `t()` 取到**对象**
`t('settings.theme')` / `t('settings.locale')` 取的是「主题/语言映射表」对象，不是叶子文案
→ 界面显示原始 key。改为语义正确的既有叶子键 `settings.appearance.theme` / `.language`。

### 2.2 Python：`notification.channel.wechat.token_failed` 三语全缺
`channels/wechat.py` 两处 `t('notification.channel.wechat.token_failed')` 在取 token 失败时使用
→ 用户看到的就是这串键名。补齐 zh_CN/en/zh_TW。

### 2.3 Python：zh_TW 补齐 83 个 GUI 文案
这些键在 zh_CN/en 都有、zh_TW 没有 → 繁体用户看到原始键名。按「短语映射 + 字符映射 + 80 条显式
覆盖」补齐（`msg_*` / `query_*` / `download_*` / `auto_run_*` / `pq_*` / `title_*` / `btn_*` 等）。
另补 en 缺失的 4 条与三语都缺的 `no_extension`。

### 2.4 新增「缺键守卫」测试（防复发）
- **后端** `tests/unit/test_i18n_completeness.py`（5 例）：扫描 `pilotstd`/`docker` 生产代码里
  所有字面量 `t("...")`/`_("...")` 键，断言**三个词典都包含**；另加 zh_TW ⊆ zh_CN 对齐守卫
  与 `wechat.token_failed` 具体回归。
- **前端** `web/src/i18n.test.ts`（+2 例）：三语扁平键集相等；`settings.theme`/`settings.locale`
  是对象、必须用叶子键。

> 这两个守卫是**整类问题**的防线：今后任何人新增 `t('...')` 却忘加词典，测试立即红。

## 3. 复核后判定「不改」的项

| 项 | 理由 |
|---|---|
| 29 处 naive `datetime.now()` | 绝大多数是**文件名/日志时间戳**（本地时间正是想要的）；业务时间统一走 `core/time_utils.py`；比较对象双方都是 naive 本地时间，口径一致 |
| 21 处「调用结果直接 `[0]`」 | 绝大多数是 `str.split(...)[0]`（split 必返回 ≥1 元素）与 `re.split(...)[0]`（同理），不是空列表风险；真正的空列表风险由已有的 `is_found()`/空检查覆盖 |
