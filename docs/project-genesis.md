## 一、项目是什么

**PilotStd — 标准文件管理工具**（GitHub: `leanmore/pilotstd`，MIT 协议）

自动识别标准号 · 多站点有效性查询 · 批量下载 · 分类归档。双端可用：PyQt6 桌面端 + Docker Web 端，共享同一引擎。

**技术栈**：Python 3.12 + FastAPI + SQLite（自研封装，无 ORM）+ Vue 3 + PrimeVue 4 + PyQt6（桌面）

**产品定位**：B 端内部工具——标准文献采集与管理平台，面向机构内部的标准情报工作人员（标准情报员、标准化工程师、图书情报管理员），非公开 SaaS；Docker 自托管部署。

## 二、起源动机（为什么要做）

> 注：可考会话记录始于 2026-07-18，但项目实际立项更早（README 版本 v0.55.33、git 提交可溯至 2026-07-14 的 `67c3d518`）。立项初期的原始对话可能未被转录保留，以下动机综合最早会话与项目现状推断：

1. **个人标准情报管理的痛点**：标准文献（国标/行标/团标/企标/国际标准）分散在数十个政府与行业协会网站，手工检索、下载、归档、跟踪废止状态极其繁琐。
2. **"数据有了，但数据是错的，且界面不好用"**（2026-07-18 用户原话）：早期抓取管线能拿到数据，但公告正文填充错误、标准名称重复拼接、日期字段大量缺失、统计数字离谱（"抓取 114705 条公告…涉及标准 96806457 项"——公告数/标准数搞反、笛卡尔积膨胀）。
3. **治理体系从零搭建**：用户希望 AI 插件"每次工作时自动遵守规范，而不是每次靠人工在指令中重复提醒"，由此催生 CLAUDE.md"三位一体"治理体系（大脑 CLAUDE.md + 肌肉 check_all.sh + 神经 pre-commit Hook）。
4. **从桌面工具演进到 Web 端**：早期为 PyQt6 桌面单机工具，后增加 Docker Web 端（FastAPI），再演进为多用户架构。

## 四、贯穿全程的工程文化

从 154 个会话中反复出现的、塑造了项目形态的协作特征：

| 特征 | 表现 |
|---|---|
| **先验再说** | 所有结论基于实证（真实数据采样 ≥3 条），禁止纯代码推导代替数据采样 |
| **证据链** | 交付必附 file:line、git diff、测试输出；报告是"执行结果"不是"待办清单" |
| **门禁即纪律** | G-010/G-012/G-028 等门禁驱动重构（拒绝削空白行/拒绝 noqa 绕过），预存错误"遇到了就修" |
| **先调查后修复** | 调查与修改严格两阶段分离，调查阶段只读，结论由用户拍板 |
| **小步快跑** | 分批提交、单任务单 commit、每步确认、痛恨拖沓留尾巴 |
| **知识沉淀** | 每个战役都沉淀为 ADR/规范/文档（三位一体），"只被执行过的门禁才算数" |
| **生产敬畏** | 三环境模型（本地/生产/混合），生产禁止直接操作，写操作先预览确认 |
