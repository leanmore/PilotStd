# PilotStd 版本管理规范

遵循语义化版本（Semantic Versioning 2.0.0），格式：`主版本号.次版本号.修订号`

## 核心规则

| 递增 | 条件 | 示例 |
|:--:|------|------|
| 主版本 (Major) | 不兼容的 API 修改 | 1.0.0 → 2.0.0 |
| 次版本 (Minor) | 向下兼容的新功能 | 0.2.0 → 0.3.0 |
| 修订号 (Patch) | 向下兼容的问题修正 | 0.3.0 → 0.3.1 |

## 当前阶段

项目处于 **0.y.z 开发初期**，API 未稳定，任何变动都可能带来破坏。

- `0.1.0` — 首个可运行版本
- `0.2.0` — 架构重构 + 公告适配器 + Web UI
- `0.3.0` — Nuitka + Release + 解析器重构
- `0.4.0` — 本地知识库架构 v4：缓存三表联动、文件名清洗、模糊匹配升级、GUI 阶段依赖
- `0.4.1` — 版本号规范化 + 项目清理 + 文档更新（441 测试全通过）
- `1.0.0`（目标）— API 定稿，生产就绪

## 发布流程

```bash
git tag v0.4.1
git push origin v0.4.1
```

CI 自动编译 Nuitka + 创建 GitHub Release + 推送 Docker 镜像。
版本号与 Git 标签严格一致，代码与版本永久关联。

## 预发布标识

- `-alpha.N` — 内部测试
- `-beta.N` — 公开测试
- `-rc.N` — 发布候选

示例：`v1.0.0-beta.1` < `v1.0.0-rc.1` < `v1.0.0`

## 原则

- 版本号永不回退，发现错误发布新的修订号
- 不滥用主版本号——仅重构代码不改变行为时不升 Major
- 每次发布 Git 标签与版本号一致
