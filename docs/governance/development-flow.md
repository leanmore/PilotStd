# 开发流程与决策请求规范 (Development Flow & Decision Request Protocol)

> **适用范围**：Claude Code 在执行任务过程中遇到歧义、规则冲突或超出授权范围时，向人类/参谋发起决策请求的标准化协议。
> **核心目标**：消除自然语言沟通的模糊性，确保每次中断都有结构化上下文、可选项和明确的责任归属。
> **前置依赖**：本规范与 `prompt-crafting-guide.md` §3 `[假设失效]` 报告格式互为补充，二者共同构成 Claude Code 的"安全中止"输出体系。
> **复核记录**：2026-09-21 复核 —— 全文对照当前实践：§1 六类触发条件、§2 模板、§3 字段约束、§4 响应协议、§7 规则固化信号均仍有效；正文引用的 3 个外部文件（`prompt-crafting-guide.md`、`local-session-notes.md`、`phase1-startup-checklist.md`）实测均存在，示例中引用的 G-033 / ADR-007 编号有效。本轮无内容修订。

---

## 1. 触发条件（满足任一即必须中止）

| 触发类型 | 具体场景 | 禁止行为 |
| :--- | :--- | :--- |
| 规则冲突 | 两条及以上规则对同一操作给出矛盾要求 | 自行选择优先级更高的规则执行 |
| 授权越界 | 需修改未列入 `操作范围` 的文件/模块 | 静默扩大修改范围 |
| 业务歧义 | 验收标准存在多种合理解释 | 按"最可能"的理解自行实现 |
| 假设失效 | `context-ref` 校验失败（见 prompt-crafting-guide §1.1） | 忽略校验继续执行 |
| 回滚缺失 | 涉及 DB 变更但 rollback 字段不完整 | 仅执行代码回滚 |
| 外部依赖未就绪 | 所需 API/服务/数据尚未可用 | 使用 mock 数据替代并继续 |

> **铁律**：以上任一条件触发时，Claude Code **禁止**输出任何代码修改、禁止写入文件、禁止执行 shell 命令。唯一允许的输出是 `[决策请求]` 或 `[假设失效]` 结构化报告。

---

## 2. `[决策请求]` 标准格式

```markdown
## [决策请求] {简短标题，≤15字}

**触发类型**: [规则冲突 / 授权越界 / 业务歧义 / 回滚缺失 / 外部依赖未就绪]
**当前任务**: {引用 prompt-meta 中的任务目标原文}
**阻塞位置**: {精确到文件名:行号 或 执行步骤编号}

### 问题描述
{用业务语言描述矛盾/缺失/歧义，≤3句话。禁止技术术语堆砌。}

### 可选方案

| 选项 | 描述 | 用户可见后果 | 关联规则 | 是否需立即执行 |
|------|------|-------------|----------|---------------|
| A | {具体动作} | {用户能感知到的变化/损失，≤20字} | G-XXX / ADR-XXX | ✅ 是 / ⏸️ 否 / 🔘 可选 |
| B | {具体动作} | {用户能感知到的变化/损失，≤20字} | G-XXX / ADR-XXX | ✅ 是 / ⏸️ 否 / 🔘 可选 |
| C | {具体动作} | {用户能感知到的变化/损失，≤20字} | 无直接关联 | ✅ 是 / ⏸️ 否 / 🔘 可选 |

**"是否需立即执行"取值定义**：

| 值 | 含义 | 决策者预期行为 |
| :--- | :--- | :--- |
| ✅ 是 | 不选择将导致当前任务无法继续或产生不可逆损害 | 必须在本次会话中做出选择 |
| ⏸️ 否 | 可安全延后，不影响其他功能或数据完整性 | 可回复"稍后处理"进入等待重启状态 |
| 🔘 可选 | 有默认兜底方案，但人工选择可获得更优结果 | 可选择、可延后、也可回复"使用默认" |

### 参谋建议（若有）
{Qwen/DeepSeek 在生成提示词时预填的建议，或运行时由参谋注入的分析。若无则标注"暂无"。}

### 需要您决定
请选择 A / B / C，或提供新方案 D（需包含上述表格全部字段）。
**超时策略**: 
- 若 30 分钟内未收到任何回复 → 自动标记 `[挂起]`
- 若收到延迟意图回复 → 标记 `[等待重启]`，等待用户显式重启指令
- 两种状态均不自动恢复、不降级执行
```

## 3. 字段填写强制约束

| 字段 | 约束 | 违规示例 |
| :--- | :--- | :--- |
| 触发类型 | 必须从 §1 六类中精确匹配，禁止自创 | "技术困难""不确定" |
| 阻塞位置 | 必须可定位，禁止"某处""相关代码" | "在数据处理部分" |
| 问题描述 | ≤3句，禁止嵌套从句，禁止代码片段 | "当调用 userService.fetch() 时因为 cache miss 导致..." |
| 可选方案 | ≥2个，≤4个；每个方案必须有独立业务影响 | 仅列"A: 按原计划" |
| 是否需立即执行 | 必须从 ✅/⏸️/🔘 三值中精确选择，禁止自定义 | "高优先级""可以等等" |
| 超时策略 | 固定30分钟，禁止动态调整 | "等待用户回复后继续" |

---

## 4. 决策响应处理协议

用户/参谋回复后，Claude Code 必须按以下流程处理：

1. **解析回复**：识别选择的选项字母或新方案内容。

1.5 **识别延迟意图**：若用户回复包含"稍后处理""暂时搁置""下次再说"等延迟语义且未给出明确时间点：
   - 将执行状态标记为 `[等待重启]`（非 `[挂起]`）
   - 输出确认消息："已标记为[等待重启]。当您准备好继续时，请发送'继续处理 [任务标题]'。"
   - **禁止**自动重试、禁止超时降级、禁止执行任何后续步骤
   - 仅在收到用户显式重启指令后，从步骤 2 继续

2. **验证完整性**：若选择新方案 D/E...，检查是否包含 §2 表格全部字段。缺失则再次输出 `[决策请求]`，标注"上一轮回复缺少必要字段"。

3. **记录决策**：将决策结果追加至 `local-session-notes.md`，格式：

   ```markdown
   ### [决策记录] YYYY-MM-DD HH:MM {标题}
   - 触发: {触发类型}
   - 选择: {选项字母}
   - 理由: {用户/参谋提供的理由原文}
   - 关联提示词: {prompt-meta 中的 target-rules}
   ```

4. **恢复执行**：仅当步骤 3 完成后，方可继续执行原任务。

5. **禁止记忆跨会话**：决策记录仅用于当前会话及后续提示词生成的上下文参考，不得作为永久规则写入三位一体体系。如需固化为规则，必须由参谋发起规则修订流程。

## 5. 与 `[假设失效]` 的关系

| 维度 | `[决策请求]` | `[假设失效]` |
| :--- | :--- | :--- |
| 触发源 | 规则/授权/业务逻辑层面 | context-ref 硬性校验层面 |
| 是否可忽略 | 不可忽略，必须获得明确选择 | 可被用户显式"忽略此检查"覆盖 |
| 选项来源 | Claude Code 或参谋生成 | 固定三类修正建议（刷新/延长/移除） |
| 记录位置 | local-session-notes.md [决策记录] | local-session-notes.md [假设失效记录] |

> **优先级**：当同一执行点同时触发两类中止条件时，先输出 `[假设失效]`，待其解决后再评估是否仍需 `[决策请求]`。禁止合并输出。

## 6. 维护责任

- 本规范由 Qwen/DeepSeek 共同维护。
- 新增触发类型需同步更新 §1 表格及 §2 模板。
- Claude Code 发现规范缺陷时，通过 `[决策请求]`（触发类型=规则冲突）上报，不得自行修改本文件。

## 7. 规则固化信号机制

### 7.1 触发条件

当 `local-session-notes.md` 中同一规则编号（按 `target-rules` 字段匹配）在 **30 天滚动窗口** 内被记录为 `[决策记录]` ≥ 3 次，且每次选择的选项方向一致（相同选项字母或语义等效的新方案），则触发规则固化评估。

### 7.2 统计侧边栏格式

`local-session-notes.md` 文件顶部必须维护以下统计区块（由 Claude Code 在每次写入 `[决策记录]` 后自动更新）：

```yaml
<!-- rule-signal-stats
window: 30d
updated: 2026-07-27T18:56:00+08:00
signals:
  - rule: G-033
    count: 3
    consistent-direction: true
    last-triggered: 2026-07-27
    status: pending-evaluation
  - rule: ADR-007
    count: 2
    consistent-direction: true
    last-triggered: 2026-07-25
    status: monitoring
-->
```

### 7.3 状态流转

| status | 含义 | 触发动作 |
| :--- | :--- | :--- |
| `monitoring` | 计数 < 3，持续观察 | 仅更新统计，无额外动作 |
| `pending-evaluation` | 计数 ≥ 3 且方向一致 | 参谋在下一次会话开始时主动输出 `[规则固化建议]`，包含历史决策摘要及拟议规则草案 |
| `evaluated` | 参谋已完成评估 | 无论是否采纳，标记为 evaluated 并重置该规则计数 |
| `rejected` | 评估后决定不固化 | 标记为 rejected，30 天内不再重复触发同一规则的评估 |

### 7.4 隔离保障

- 统计侧边栏仅为信号，不构成规则本身
- 规则固化必须经过完整的三位一体修订流程（提案 → 评审 → 批准 → 发布）
- Claude Code 禁止基于统计侧边栏自行修改任何治理文档
