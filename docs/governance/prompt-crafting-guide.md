# 提示词生产规范 (Prompt Crafting Guide)

> **适用范围**：Qwen / DeepSeek（网页端参谋）为 Claude Code（IDE执行官）生成执行提示词时必须遵守的协议。
> **核心目标**：确保提示词具备机器可解析的元数据、业务可读的执行指令、以及失败可恢复的安全边界。

---

## 1. 提示词结构强制要求

每个发送给 Claude Code 的提示词必须由两部分组成：**元数据头** + **正文**。顺序不可颠倒。

### 1.1 元数据头 (Prompt Meta)

使用 YAML 格式包裹在 HTML 注释中，置于提示词最顶部。Claude Code 必须在执行前解析此区块。

```yaml
<!-- prompt-meta
target-rules: [G-033, ADR-005]          # 预期触发的三位一体规则条款编号
assumptions:                            # 本次执行隐含的前提条件（业务语言描述）
  - "分支基于 latest/main 且无未提交变更"
  - "v44迁移脚本已在 src/migrations/ 下创建"
context-ref: "local-session-notes.md#2026-07-27-v44-rollback"  # 可选：指向本地会话笔记锚点，用于动态假设校验
assumptions-max-age: 7d                 # 可选：覆盖默认3天有效期
rollback: "git revert HEAD"             # 执行失败时的精确恢复命令
-->
```

**⚠️ context-ref 验证协议（v2 强制）**

当 `context-ref` 字段存在时，Claude Code 必须在执行任何修改前完成以下**硬性检查**（禁止对锚点内容做语义理解或等效性判断）：

1. **存在性检查**：锚点在 `local-session-notes.md` 中是否存在？
   - ❌ 不存在 → 立即中止，输出 `[假设失效]`。

2. **时效性检查**：锚点对应条目的时间戳是否满足业务有效期？
   - 若元数据中声明了 `assumptions-max-age: 7d`（可选），且锚点时间距今超过该值 → 立即中止，输出 `[假设失效]`。
   - 若未声明 `assumptions-max-age`，**默认有效期为 3 天**。

3. **文件指纹检查**（仅当 assumptions 涉及具体文件时）：
   - 提取 assumptions 中提及的文件路径，计算其 SHA-256。
   - 与锚点条目中记录的 `file-hashes`（若有）比对。
   - ❌ 哈希不匹配 → 立即中止，输出 `[假设失效]`。

4. ✅ 以上三项全部通过 → **静默继续**。禁止对锚点文本内容做任何"是否过时""是否一致"的语义推理。

> **设计原则**：将"过时"的判断责任从 AI 语义理解转移至可机器验证的硬指标（时间戳、文件哈希）。AI 不具备判断"业务语义是否过时"的能力，强行赋予此责任必然导致幻觉。

**⚠️ rollback 字段分级规格**

| 变更类型 | rollback 字段要求 | 示例 |
|----------|------------------|------|
| 纯代码/配置变更 | 单条 git 命令 | `"git revert HEAD"` |
| 涉及数据库迁移/结构变更 | 必须包含两条命令：1. 代码回滚 2. 迁移回滚脚本（含完整路径） | `"git revert HEAD && node src/migrations/v44-schema-check.rollback.ts"` |
| 涉及外部服务/API 调用 | 必须包含补偿操作说明 | `"git revert HEAD # 需手动调用 /api/orders/cancel 补偿"` |

> **强制约束**：当 `target-rules` 中包含任何 `G-DB-*` 或 `ADR-DB-*` 规则时，`rollback` 字段若仅为单条 git 命令，Claude Code 必须拒绝执行并输出 `[回滚方案不完整]` 报告。

### 1.2 正文结构

正文必须包含以下 5 个章节，使用二级标题分隔：

```
## 任务目标
## 操作范围
## 执行步骤
## 验收标准
## 文档更新要求
```

#### 任务目标

- 一句话描述，仅使用业务语言。
- 禁止出现函数名、变量名、文件路径等技术术语。
- 示例："让用户在订单列表页能按下单时间倒序查看历史订单。"

#### 操作范围

- 列出本次修改涉及的文件/模块路径。
- 明确标注"只读"或"可写"。
- 示例："src/pages/orders/list.vue（可写）、src/api/order.ts（只读）"

#### 执行步骤

- 按顺序编号列出。
- 每步以动词开头（创建/修改/删除/移动）。
- 禁止模糊动词："尽量"、"考虑"、"建议"、"适当"。
- 示例："1. 在 list.vue 的 `<script setup>` 中添加 `sortByTime` 响应式变量..."

#### 验收标准

- 可客观判断的成功条件。
- 优先使用用户可见行为描述，其次使用代码断言。
- 示例："页面加载后，订单列表默认按下单时间降序排列；点击表头可切换升序/降序。"

#### 文档更新要求

- 明确列出本次修改需同步更新的文档及具体章节。
- 若无需更新文档，必须显式声明："本次修改不涉及文档变更。"

## 2. 质量红线（违反即拒绝执行）

| 红线 | 说明 | 违规示例 |
|------|------|----------|
| 禁止模糊动词 | 不使用"尽量/考虑/建议/适当/可能" | "尽量优化性能" |
| 禁止隐式假设 | 所有前提必须写入 `assumptions` | 正文中写"假设数据库已连接"但未在元数据声明 |
| 禁止无回滚方案 | `rollback` 字段不可为空 | 留空或写"手动处理" |
| 禁止纯技术目标 | 任务目标必须含业务价值 | "重构 UserService 类" |
| 禁止开放决策 | 执行步骤中不包含需运行时判断的逻辑 | "根据实际情况选择合适的缓存策略" |

---

## 3. `[假设失效]` 报告格式

当 `context-ref` 校验失败时，Claude Code 必须输出以下结构化报告（而非普通文本回复）：

```markdown
## [假设失效] {简短标题}

**失效锚点**: `local-session-notes.md#2026-07-27-v44-rollback`
**失败原因**: [存在性缺失 / 时效性过期(>3d) / 文件哈希不匹配]  ← 三选一
**诊断详情**: 
  - 锚点时间: 2026-07-24 10:00
  - 当前时间: 2026-07-27 18:49
  - 已超过默认3天有效期
**影响**: 无法确认前提条件仍成立，强行执行可能导致数据不一致
**建议修正**: 
  - A: 刷新上下文（重新运行相关脚本/命令以生成新锚点）
  - B: 显式延长有效期（在 prompt-meta 中添加 `assumptions-max-age: 14d`）
  - C: 移除 context-ref 依赖（改为静态 assumptions）

**需要您决定**: 选择 A / B / C，或回复"忽略此检查"强制继续（不推荐）
```
