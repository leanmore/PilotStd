================================================================
【治理框架通知】PilotStd 能力遗产治理框架已正式启用
================================================================

致全体开发者：

为避免非功能性能力（后台线程、定时心跳、观测日志、缓存等）在
代码重构中静默丢失，项目已建立"能力遗产治理框架"，自 2026-06-22
起正式生效。

----------------------------------------------------------------
背景
----------------------------------------------------------------
2026-05-31 至 2026-06-22 期间，stress_01_pipeline.py 中的
ProgressReporter（定时进度报告）和 heartbeat()（心跳线程）在 v4.1
重构归档时静默丢失，12 天后才被用户发现。

此事件触发了治理框架的建立。

----------------------------------------------------------------
核心要求（5 条）
----------------------------------------------------------------
1. 重构前：查阅 docs/governance/capabilities_registry.md 确认影响范围
2. 重构中：逐项迁移或明确放弃，commit message 中说明理由
3. 重构后：运行 python tests/test_observability.py --check-all，
   零 FAIL 方可提交
4. 归档文件前：运行 bash scripts/extract_capabilities.sh <file>，
   确保迁移完成
5. PR 提交时：必须填写"能力迁移状态"表（PR 模板中已包含）

----------------------------------------------------------------
CI 已集成守护
----------------------------------------------------------------
- test_observability.py --check-all 若 FAIL，将阻断合并
- 登记簿中存在 migrating 条目，将阻断合并

----------------------------------------------------------------
快速开始
----------------------------------------------------------------
# 重构前：提取目标文件的能力清单
bash scripts/extract_capabilities.sh pilotstd/query/engine.py

# PR 提交前：运行自检
python tests/test_observability.py --check-all

# 确认无迁移遗留
bash scripts/check_no_migrating.sh
