# P3 人工审查 Checklist

> 适用对象：唯一验收者
> 使用时机：Claude Code 提交 PR 后、Approve 前
> 原则：PR 模板勾选 ≠ 审查通过。本清单验证"为什么正确"，而非"是否做了"

## G-035 测试联动 · 语义验证

- [ ] 测试断言的**业务含义**与生产代码变更意图一致（非仅数值/字符串匹配）
- [ ] 新增/修改的测试覆盖了变更的**边界场景**，而非仅 happy path
- [ ] 若 PR 标注"N/A"，该理由在业务上下文中成立（非技术偷懒）

## G-036 文档联动 · 知识完整性

- [ ] 更新的文档**可读性达标**：新人无需读代码即可理解变更影响
- [ ] ADR 记录包含**决策背景与替代方案**，非仅结论
- [ ] `docs/reference/` 中的规范变更有**迁移指引**（如旧写法→新写法示例）
- [ ] `docs/superpowers/specs/` 的 spec/plan 变更与 `AGENTS.md` 触发条件**双向同步**
- [ ] 若某条触发规则标"N/A"，确认该规则在本次变更中确实不适用（非遗漏）

## G-037 触发条件对齐 · 治理一致性

- [ ] `AGENTS.md` 中的触发条件描述与 `index.md` 索引条目**语义等价**（非仅字符串匹配）
- [ ] 若存在差异，差异有明确治理理由（如渐进式迁移）并已记录

## G-038 历史遗留错误 · 质量趋势

- [ ] 本次提交**未引入新的 noqa/type-ignore**（即使 CI 通过）
- [ ] 若清理了历史错误，确认清理方式**不掩盖真实问题**（如用宽泛类型替代精确类型）
- [ ] 整体代码健康度**持平或提升**（非以新功能为名劣化质量基线）

## 审查结论

- [ ] 所有勾选项均通过，或失败项已有明确修复承诺与跟踪编号
- [ ] 批准合并 / 请求修改（附具体反馈）
