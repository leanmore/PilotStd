## 1. 七个结构性问题（带证据）

### 1.1 三个"文档入口"并存且互相不一致

| 入口 | 体量 | 覆盖情况 |
|---|---|---|
| `docs/index.md` | 33 行、12 条 | 只列触发式必读文档；受 G-037 硬约束 |
| `docs/DOCUMENTATION_MAP.md` | 133 行 | 较全，但不认 `docs/debt/`、`docs/records/`、`docs/technical-debt.md`、`docs/reference/download-pipeline.md` |
| `docs/inventory/all_docs_list.md` | 267 行 | 2026-08-19 的**原始文件清单**（含 venv 噪声），不是索引 |

**关键约束**：G-037 用 **basename 集合相等**比较 `index.md` 表格行与 `AGENTS.md` §8.1 表格行——`index.md` **不能扩成全量目录**，多一行就红。所以"入口唯一"只能做成：`index.md` 保持 12 行（触发式），以**列表项（非表格行）**指向 `DOCUMENTATION_MAP.md` 作为全量目录。

### 1.2 "归档"有三套互相矛盾的协议

| 出处 | 规定 | 冲突点 |
|---|---|---|
| `docs/development/documentation-policy.md` §五 | 移到 `docs/archive/YYYY-MM-DD/`，并在归档目录 README 记录原因 | 该路径是 CI 黑名单，新增即失败 |
| `docs/plans/README.md` | 完成后提炼 ADR → 移入 `docs/archive/` | 同上 |
| `scripts/check_g_032_doc_health.py:67` | 文件名含 `.archived.` 视为归档件，豁免新鲜度/交叉引用检查 | 与上面两套都不是同一做法 |
| `documentation-policy.md` 末尾 | 新归档文件"原则上不入仓" | 与"移入 docs/archive/"自相矛盾 |

→ 这就是"应该归档的归档处理"落不了地的根因：**没有唯一正确的归档动作**。

### 1.3 黑名单路径让部分目录"无法归档"

`docs/superpowers/`（17 篇）与 `docs/pending/`（1 篇）整段是黑名单：**原地改名为 `*.archived.md` 仍会命中路径黑名单而失败**（repo-compliance 用 `--diff-filter=AR`，改名后的目标路径按新增校验）。这两处只有两个合规出口：移出仓库，或删除（内容在 git 历史里）。

`docs/archive/` 同为黑名单 → **现有 67 篇只能原样保留，不能整理、不能改名**。这一点必须写进团队共识，否则下次还会有人去搬。
