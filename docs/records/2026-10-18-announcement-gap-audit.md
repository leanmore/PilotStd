## 三、根因分类

| 模式 | 例子 | 解析器旧行为 |
|---|---|---|
| 前缀含数字/后缀 | `DB52T 1078-2026` | 旧正则只允许“字母+一个数字段”，`DB52T` 不匹配 |
| 前缀含多个斜杠 | `NB/SH/T 0001-2026` | 只允许一个 `/字母` 段 |
| 前缀后是斜杠+空格 | `DB11/ 2567-2026` | 前缀不接受尾部 `/` |
| 前缀后有连字符 | `SJ/T-12117-2026` | 序号前只允许空白/斜杠 |
| 连接符被误打成汉字/西里尔字母 | `HG/T 6488 一 2026` | 只认 `—`/`-`，整行跳过 |
| 前缀中间有空格 | `QB T 1750-2026` | 前缀不接受空格分段 |
| 分册号多段 | `SJ/T 11460.6.1-2025` | 只允许一个 `.部分号` |
| 全角连接符 | `－`/`／`/`？` | 未归一化 |

## 四、处置

1. 解析器已泛化前缀/分隔符（`STD_CODE_PATTERN` + `_normalize_code_text`），上述 9/10 月缺口在**本地重解析**中已全部补齐；
2. 部署后需对受影响公告逐个触发重新解析（`POST /api/announcements/{announce_no}/parse`），已完成的公告不会自动重抓；
3. 后续按同一方法审计 2026 全年及历史公告，并增加“源站计数 vs 入库计数”巡检，避免静默缺口。
