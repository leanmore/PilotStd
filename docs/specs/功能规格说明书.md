## 1. 概述

本软件面向标准化工作者、企业档案管理人员，提供标准文件的自动识别、有效性查询、下载、归类、过期处理等功能。支持 **Windows 11** 原生运行，后期提供 **Docker** 版本。

### 1.1 法规依据

根据《国家标准管理办法》（2023年3月1日起实施）：

- 强制性国家标准代号：**GB**
    
- 推荐性国家标准代号：**GB/T**
    
- 国家标准样品代号：**GSB**
    
- 指导性技术文件代号：**GB/Z**
    

行业标准代号依据全国标准信息公共服务平台（`std.samr.gov.cn`）公示清单。

### 1.2 核心价值

- 自动化处理标准文件的整理与更新跟踪
    
- 解决标准号命名不规范、网站交互复杂（验证码、跳转）等问题
    
- 明确采标标准的版权限制，避免无效下载；提供用户自担风险的离线存档选项
    
- 提供可配置的本地文件夹结构，便于长期管理
    

### 1.3 隐私与合规声明

软件明确告知用户：所有标准号查询请求均通过用户本地IP发出，软件开发者无法获取用户的查询记录。用户主动上传的日志文件可能包含查询历史，请自行决定是否分享。

## 3. 标准编号规范

### 3.1 标准文件编号格式

标准文件编号由 **文件代号**、**顺序号** 及 **发布年份号** 构成，格式为：

text

{文件代号} {顺序号}—{年份}

- **文件代号**：由大写拉丁字母（汉语拼音字母）和/或符号 `/` 组成，例如 `GB`、`GB/T`、`GB/Z`、`GSB`、`SH/T` 等。
    
- **顺序号**：阿拉伯数字，通常 1~5 位。
    
- **发布年份号**：四位阿拉伯数字。
    
- **连接号**：一字线 `—`（Unicode U+2014）。**已统一为短横 `-`，不可更改**。
    

### 3.2 部分号（细分标准）

当标准分为多个部分时，在顺序号后用小数点连接部分号，例如 `GB/T 1.1—2020`。

### 3.3 Windows 文件名兼容处理

Windows 文件名不允许包含 `/`，因此在保存文件时需将文件代号中的 `/` 去除（如 `GB/T` → `GBT`）。

### 3.4 文件命名规范

默认格式：`{文件代号（去除/）} {顺序号}[.{部分号}]—{年份} {标准名称}.pdf`

### 3.5 原始下载文件名的解析

从国家标准全文公开系统下载的文件名示例：`GBT+1.1-2020.pdf`。解析规则：

- 支持分隔符：`+`、空格、`-`、无分隔符。
    
- 将 `+` 视为普通分隔符。
    
- 提取无斜杠文件代号、顺序号、部分号、年份，再映射为逻辑文件代号。
    

> **增强容错**：当正则匹配失败时，进入模糊匹配模式——提取文件名中所有数字串，判断符合“年份（4位）+顺序号（3~5位）”模式的候选，进行逆向推导。同时，对文件名进行“清洗”：去除方括号、特殊符号等。

## 4. 功能详细说明

### 4.0 操作总流程

```
主线: 导入 → 扫描 → 查询 → 下载 → 规范化 → 归档

                           ┌─ exact+现行/即将实施 → 下载 → 规范化 → 归档(标准/)
 导入→扫描→查询(打分) ────├─ exact+废止 → 下载(跳过) → 规范化 → 归档(过期作废/)
                           ├─ exact+被代替 → 归入过期作废，替代标准通过正常扫描获取
                           └─ 非exact(newer/older/code_only/mismatch)
                                → 待确认(等以后重查，不进入后续流程)
```

**查询阶段**：逐站搜索（站间串行），路由分流：GB→std_gov→njbz365→csres，行业→hbba→njbz365→csres，ISO/IEC→iso_gov→njbz365，国外→njbz365。遇 exact 终止。结果比对打分：
- exact(100)：代号、顺序号、年份（含部分号）全匹配
- newer(80)：代号+顺序号匹配，年份更新
- older(50)：代号+顺序号匹配，年份更旧
- code_only(20)：仅代号匹配
- mismatch(0)：无匹配

**查询后自动分类**（`_classify_after_query`，v1.15 重构）：

```
查询结果(每对 parsed+result):
├─ 规则0: 非exact(newer/older/code_only/mismatch) → 待确认(pending)，等重查
├─ 未查到/未知/状态缺失           → 待确认(pending)
├─ 待确认(匹配置信度不足)          → 待确认(pending)
├─ 废止/被代替/作废 + newer + GB   → 下载(远程版即替代标准)
├─ 废止/被代替/作废 + !newer       → 过期处理(无替代，直接废止)
│   └─ 无 replaces 时跨站补查(njbz365→csres→hbba)
├─ 现行/即将实施 + newer + GB      → 下载
├─ 现行/即将实施 + !newer          → 跳过(已是最新)
└─ 非 GB 类                       → 跳过下载(归档)
```

分类结果存储为 `_download_list` / `_expire_list` / `_pending_list`。`download()` 只读取列表，不重复决策。

**replaces 获取策略**：五个适配器中 csres/njbz365/hbba 提供详情页替代关系。只在 `query_with_strategy` 选出最优结果后查一条详情页提取 replaces。std_gov 无此能力时由 `_resolve_replaces()` 跨站补查。详情页请求使用配额保底(csres 30/njbz365 50/hbba 30)，不占用搜索配额。

**下载阶段**：可下载的下载，采标跳过（弹出版权提示），无链接导出列表。下载后文件命名为规范格式。

**规范化阶段**：检查文件名是否符合 `{代号(去/)} {顺序号}[.{部分号}]—{年份} {标准名称}.pdf` 格式。符合跳过，不符合重命名。

**归档阶段**：
- 现行/即将实施 → 移动到 `标准/{基础代号} {行业名}/`
- 废止/被代替 → 移动到 `标准/{基础代号} {行业名}/过期作废/`

**主流程**：导入 → 扫描 → 查询 → 下载 → 规范化 → 归档，六步串联。

### 4.1 文件扫描与标准信息提取（已完成实现）

**输入**：用户导入的一个或多个文件夹（支持递归子目录）。

**处理过程**：

1. 遍历文件夹中的所有文件（支持 `.pdf`、`.doc`、`.docx`、`.txt`）。  
    **注意**：对于文件夹内名为 `过期作废` 的子文件夹（及其所有子内容），**不进行扫描遍历**，直接跳过。
    
    - 目的：避免将已标记为过期的标准文件重复纳入解析列表，减少无效处理。
        
    - 实现方式：在递归遍历目录时，检查当前目录名是否为“过期作废”（用户可在设置中自定义该文件夹名称），若是则跳过该分支。
        
2. 对每个符合后缀名的文件，从文件名中解析标准编号：
    
    - 使用正则表达式匹配标准格式（自动纠正常见错误，如 `+`、无空格等情况）。
        
    - 支持识别部分号（如 `1.1`）。
        
    - 通过内置映射表将无斜杠文件代号转换为逻辑文件代号。
        
3. 提取标准名称：
    
    - 若年份号后还有文本，则作为标准名称候选（去除扩展名）。
        
    - 若文件名中无标准名称，则暂时留空（后续通过查询网站填充）。
        
4. 存储解析结果到内部数据库或临时表。
    

**输出**：

- CSV/JSON，包含字段：  
    `原始文件名`、`文件代号`（逻辑）、`顺序号`、`部分号`、`年份`、`标准完整编号`、`标准名称`（若有）
    

**性能目标**：扫描 1000 个文件 ≤ 5 秒。

**实现状态**：已完成，对应模块 `pilotstd/scan/scanner.py` 和 `pilotstd/scan/parser.py`，单元测试通过。已接入 GUI 的工具栏"▶ 运行"和"运行→文件扫描"菜单，扫描结果填充工作区表格。

### 4.2 标准有效性查询（已完成实现）

**内置查询网站**（5个）：

- 国家标准全文公开系统（`openstd.samr.gov.cn`，适配器 `std_gov`）
- 行业标准信息服务平台（`hbba.sac.gov.cn`，适配器 `hbba`）
- ISO官网（`www.iso.org`，适配器 `iso_gov`）
- 工标网（`csres.com`，适配器 `csres`）
- 南京标准公共服务平台（`njbz365.cn`，适配器 `njbz365`），2026-05-25上线，API走同域BFF代理(/apis/)+csrf_token+sign(MD5)
- 地方标准信息服务平台（`dbba.sacinfo.org.cn`，适配器 `dbba`），5/30新增，`POST stdQueryList` API，支持全国省/市地方标准（DB11, DB35/T, DB3501/T 等），`reviseStdCodes` 字段直接提取代替关系

**查询适配器**（6个）：`std_gov` / `hbba` / `iso_gov` / `csres` / `njbz365` / `dbba`，均位于 `pilotstd/query/adapters/` 目录下。

**SiteRotator 站点轮转冷却机制**：管理请求频率，同一站点连续请求后自动冷却等待，防止 IP 被封。

**NetworkMonitor 网络异常监控**：临时性网络错误（超时、连接重置等）自动重试 1 次，汇总报告网络状态。

**query_interval 抖动间隔**：批量查询时，站间请求间隔在 0.5~1.5 秒范围内随机抖动，避免固定频率触发反爬。

**查询方式**：单个/批量导入，自动识别验证码（见4.7）。

**查询结果字段**：标准号、标准名称、状态、代替标准、实施日期、归口单位、采标关系、是否采标、来源网站、发布日期、废止日期、match_status(精确匹配度)、exact计数。

**双重校验采标**：不仅依据“采标关系”字段，还校验“发布机构”或“标准状态”，避免误判。

**查询完成弹窗**：批量查询完成后弹出模态对话框，显示：
- 已就绪（直接归档）数
- 需规范化后归档数
- 已废止数
- 待确认（需人工核实）数
- 未查询到数

**待确认清单**：非 exact 匹配（newer/older/code_only/mismatch）的结果自动标记"待确认"。只有置信100分的精确匹配进入后续流程，待确认项保留在列表中等待以后重查。

**本地知识库（v1.14 重构）**：

三表联动架构——`standard_info_cache`（网络查询结果）、`file_index`（文件身份+SHA）、`announcement_cache`（公告变更记录）——构成标准信息的知识闭环。

- **写入规则**：仅 exact(100分) 写入 `standard_info_cache`。newer/older/code_only/mismatch 均不写。写入时附带 `source="network"`。
- **读取规则**：缓存可信，不设 TTL。失效唯一途径：公告触发 + 网络复核确认（不直接覆盖）。
- **无公告覆盖的标准**（API/DIN/ISO等）保鲜靠用户手动刷新。
- **多源冲突**：按分数裁决，exact(100) > newer(80) > older(50) > code_only(20) > mismatch(0)。核心字段只信主站点，辅助字段可从其他站点补。
- **下载回写**：下载成功 → 写 file_index → 更新缓存状态（老文件废止→新文件现行；老文件现行→新文件待实施）。
- **公告联动**：公告标记失效 → 网络复核 → 确认后更新缓存状态并追加 status_history JSON 字段。
- **公告触发**：从工具菜单移至工具栏按钮，紧随"一键处理"之后。手动触发，不在启动时自动运行。
- 用户决策写 `pending_lookup`（不写缓存），手动录入 `source="manual"`。

### 4.3 标准文件下载（已完成实现）

**下载前处理**：
- **去重**：下载前检查目标路径是否已存在同名文件，存在则跳过，避免重复下载。
- **showGb→viewGb 流程恢复**：openstd 下载流程从已废弃的 `showGb` 路径恢复为标准 `viewGb` 路径。
- **openstd hcno 直接搜索**：对已知 hcno 的标准，直接构造详情页 URL 跳过搜索结果页，减少一次 HTTP 请求。

#### 4.3.1 常规下载

支持并发、重试、代理等配置。单个文件采用单线程下载。

#### 4.3.2 国家标准全文公开系统的特殊处理

重定向到 `c.gb688.cn`：

- 会话保持
    
- 四位数字验证码识别（ddddocr + 手动）
    
- 预览页面 CSS 精灵图解析（**默认关闭**，需用户手动开启“离线存档模式”并确认风险声明后方可使用）
    
- 反调试绕过（Playwright）
    
- DRM 保护兜底
    

#### 4.3.3 采标标准的处理

- 禁止下载，弹出版权提示。
    
- 输出不可下载列表。
    
- CSS 精灵图拼接功能仅在用户明确开启“离线存档模式”且同意相关法律风险后生效。
    

#### 4.3.4 无法下载的情况

以下情况标准文件无法自动下载，软件分类处理：

**一、未到新标准下载期**

新标准发布后，需等待 28 个自然日（≈20 个工作日）才能在下载网站获取文件。

- 记录到 `download_queue` 表（标准编号、发布日期、预计可下载日）
- 下次启动时自动检查：已过 28 自然日 → 提示用户确认 → 进入下载步骤
- 旧标准不等待，先行规范化→归档(过期作废/)
- 提示文案："新标准 GB/T XXXXX-2026 预计 YYYY-MM-DD 后可下载，届时将自动提醒"

**二、采标标准（版权限制）**

- 禁止下载，弹出版权提示
- 记录到不可下载列表

**三、网站无下载链接**

- 提示用户，导出标准信息（标准编号、名称、来源网站），用户自行获取
- 旧标准照常规范化→归档(过期作废/)

**四、其他下载失败**

- 网络错误、验证码失败等 → 网络层 urllib3 Retry 3 次（仅 429/5xx），业务层不自动重试
- 网络层重试耗尽 → 记入失败列表，用户可手动重试

所有无法下载的情况统一输出 CSV 列表，列包括：
- 序号
- 标准完整编号（逻辑编号）
- 标准名称
- 失败原因

### 4.6 标准更新监控（公告模块已完成实现）

#### 4.6.1 公告自动更新（已完成实现）

`pilotstd/announcement/` 模块已完整实现，采用适配器模式（`base.py` + `engine.py` + `adapters/samr_gb.py` + `samr_hb.py` + `samr_db.py` + `parser.py` + `matcher.py`）。

**数据来源**：
- 国家标准公告（`nocGB`）+ 行业标准公告（`nocHB`）+ 地方标准公告（`nocDB`），覆盖发布/废止/代替
- 行业标准备案月报（`nocHB`）：76 个行业标准的月度更新汇总
- 复审结论公示（`withdrawnReview`）：标准有效期延续或修订

**工作流程**：
1. 启动时拉取上次抓取日期之后的新公告
2. 下载附件（.wps），解析标准清单
3. 与 `file_index` 交叉比对，命中则更新 `standard_info_cache` 状态
4. 检测到变更 → Windows 通知用户
5. 更新抓取日志 `fetch_log`

**反反爬机制**：
- **Session 复用**：同一站点多次请求共用 HTTP Session，减少 TLS 握手开销，降低被识别概率。
- **UA 轮换**：每次请求从内置 UA 池随机选取 User-Agent，模拟多浏览器访问。
- **请求抖动（Jitter）**：请求间隔在基准延迟基础上叠加随机偏移（±30%），避免固定频率触发风控。

**启用控制**：
- 在"设置"中提供开关：`标准公告自动更新`
- **Windows 版默认关闭**，用户手动开启
- **Docker 版默认开启**，首次启动时弹窗提示

## 7. 标准代号支持

### 7.1 数据来源

根据全国标准信息公共服务平台（`std.samr.gov.cn`）及国际标准化组织公开信息，本软件内置：
- **中国标准代号**：国家标准（GB/GB/T/GB/Z/GSB）及 76 类行业标准
- **国际标准代号**：ISO、IEC、ITU、CAC、WHO
- **主要发达国家标准**：ANSI、ASTM、DIN、BS、JIS 等
- **区域性标准**：EN、CSA、NF 等

具体清单详见同级目录下的 `附录一 标准代号完整清单.md`。

### 7.2 动态更新

- 软件启动时（可配置频率）自动访问全国标准信息公共服务平台，检查是否有新发布的代号。
    
- 若有更新，提示用户一键更新映射表。
    
- 支持用户手动添加或修改代号及对应的名称。
    

### 7.3 推荐性与强制性标准的处理

- **中国行业标准**：
  - **强制性标准**：直接使用代号，不加 `/T`，例如 `GA`。
  - **推荐性标准**：在代号后加上 `/T`，例如 `YD/T`。文件名存储为无斜杠形式（`YDT`）。
- **国际/国外标准**：不区分强制/推荐，直接使用原始代号（如 `ISO`、`ASTM`），不生成 `/T` 变体。
    

### 7.4 解析与命名中的文件代号处理

- **映射表生成规则**：
  - 中国行业代号：自动生成两条（`{代号}T` → `{代号}/T` 和 `{代号}` → `{代号}`）
  - 国际/国外代号：直接映射（`ISO` → `ISO`），不生成 `/T` 变体
        
- **生成文件名时**：对于逻辑文件代号（含 `/`），按规则去除 `/`：若以 `/T` 结尾，则去除 `/T` 并添加 `T` 到末尾；若包含其他斜杠（如 `GB/Z`），则直接去除斜杠。
