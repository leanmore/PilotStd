# 标准查询站点分类方案 v1.1

## 1. 目的
对项目中的所有标准查询站点进行结构化分类，明确各站点的覆盖范围、核心能力和适用场景，为路由策略提供基础数据支撑。

## 2. 分类体系概览
站点分为两大层级（Level 1）：
- **综合站点**：覆盖多种标准类型或多个行业领域，不局限于特定垂直领域。
- **特色站点**：聚焦于单一标准类型、特定行业或特定领域的标准查询。

## 3. 分类定义（Level 2）

### 3.1 综合站点 (Level 1) 的子分类

| 子分类 (Level 2) | 定义 | 典型特征 |
| :--- | :--- | :--- |
| **国内综合** | 能查询国内多种标准类型（如国标GB、行业标准JB/NB/SH、地方标准DB等） | 覆盖 ≥ 2种国内标准类型，不覆盖国际标准 |
| **全综合** | 既能查询国内标准，也能查询国际标准（ISO/IEC/IEEE等） | 同时覆盖国内和国际标准，或通过通用搜索无差别获取各类标准 |

### 3.2 特色站点 (Level 1) 的子分类

| 子分类 (Level 2) | 定义 | 典型特征 |
| :--- | :--- | :--- |
| **按标准类型区分** | 聚焦于特定的一种标准类型，或同维度的多种标准类型 | 如：仅查计量标准(JJG)、仅查地方标准(DB)、或国际标准聚合(ISO+IEC+IEEE) |
| **按领域区分** | 聚焦于特定行业或行政领域的标准 | 如：交通(JT)、环保(HJ)、食品(GB食品类)、铁路(TB) |

## 4. 判定标准与规则

### 4.1 综合 vs 特色的边界
- 若站点配置了 `is_general=True` 且覆盖多种标准类型 → 综合
- 若站点配置了特定的 `industries`（非空）且仅服务于该领域 → 特色（按领域区分）
- 若站点仅配置了单一标准类型前缀（或同体系子分类） → 特色（按标准类型区分）

### 4.2 国内综合 vs 全综合的边界
- 适配器代码中是否包含国际标准（ISO/IEC/IEEE等）的解析逻辑或专属查询入口？
- 若有 → 全综合；若仅处理国内标准代号 → 国内综合
- **注意**：对于通用搜索类站点（无前缀过滤），若未实际验证国际能力，需标记为"全综合（待验证）"

### 4.3 标准类型计数规则（核心规则）
在判定是否满足"多种标准类型"时，必须遵循以下计数规则：
1. **同一标准代号体系下的子分类计为 1 种**。例如：`GB/GB/T/GB/Z` 计为 1 种（国标体系）；`JT/JTG/JTS` 计为 1 种（交通体系）。
2. **不同标准代号体系各计为 1 种**。例如：`GB`、`JB`、`NB`、`SH`、`HJ` 各计为 1 种。
3. **地方标准 `DB` 计为 1 种**独立类型。

### 4.4 冲突解决优先级
当站点特征存在冲突时，按以下优先级判定：
1. 代码硬过滤逻辑（如强制校验 ISO 关键词） > 配置文件声明
2. 实际查询能力（经验证） > 理论配置范围

**案例说明**：mee（生态环境部）的 `std_prefixes=[HJ, GB]` 按计数规则是 2 种类型，但归为"特色（按领域区分）"而非"国内综合"。原因：其 GB 仅限环保类国标，非全领域国标，`industries=[环保]` 的领域约束优先级高于类型数量（4.4 规则1生效）。

## 5. 输出格式规范

### 5.1 字段定义
每个站点需输出以下 10 个字段：

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| `site_name` | string | 站点标识符 |
| `classification_level1` | enum | 综合 / 特色 |
| `classification_level2` | enum | 国内综合 / 全综合 / 全综合（待验证） / 按标准类型区分 / 按领域区分 |
| `industries` | list | 覆盖的行业领域列表（来自配置） |
| `std_prefixes` | list | 支持的标准前缀列表（来自配置） |
| `std_prefixes_source` | enum | 前缀来源：config_declared / inferred / mixed |
| `coverage_completeness` | enum | 全量 / 部分 / 未知 |
| `intl_verified` | bool | 国际标准能力是否经实际查询验证（仅全综合/待验证站点需关注） |
| `notes` | string | 特殊能力、边界特征或重要标注 |
| `judgment_basis` | string | 判定理由（一句话，需引用代码或配置证据） |

### 5.2 Notes 标注规范
- 对于仅覆盖 GB/GB/T/GB/Z 的站点，必须在 notes 中标注：**"国标专用平台（覆盖全领域国标）"**，以区别于计量(JJG)等窄类型特色站。
