# ADR-015: 标准查询路由引擎 v2.0 — 三级漏斗路由

> 日期：2026-08-21（决策于 2026-08-17 会话 F154）
> 状态：✅ Accepted（决策已定，v2.0 分四阶段实施中）
> 来源：A4 会话转录提炼（`~/.claude/projects/d--PilotStd/` F153/F154）
> 关联：[[ADR-012]]

---

## 背景

v1.0 路由基于 scorer.py 扁平评分（权重 +30/+20/-10），存在失效场景：`scorer.py:166` 前缀匹配 `query.startswith("GB")` 时 mee 也 +30，国标查询被误路由到生态环境部适配器（mee）。21 个适配器各自维护独立配置，无统一能力模型；query_metrics 无 per-site 维度，历史命中率无法回填。

## 决策

1. **能力模型**：`config/site_capabilities.yaml`（21 站点）——将站点分类 v1.1 成果（标准类型计数规则 + intl_verified 实证字段）转化为路由系统可消费的结构化能力模型。
2. **三级漏斗路由**：
   - 分支 A（有标准号前缀）：国际 → 跳过 L1 → L2 全综合 → L3；国内 → L1 精准匹配 → L2 国内综合 → L3
   - 分支 B（纯关键词）：跳过 L1/L2 直接 L3
   - 设计原则：L1 只处理国内精准、L2 有明确标准号未命中的兜底、L3 模糊探索
3. **意图解析规则库驱动**（正则 + 关键词词典，不调用 LLM），识别优先级：标准号前缀 > 关键词匹配。
4. **数据闭环**：异步 JSONL 日志 + 后台线程埋点（绝不阻塞主查询链路）；backfill 工具只更新 `historical_hit_rate`/`avg_latency_ms` 两字段 + 自动备份 + 同步 Registry；v1/v2 隔离（`ROUTING_ENGINE_VERSION=v2` 才全量埋点）。

## 核心约束

- **零删除 v1 代码**、性能零退化、灰度优先（v1 清理需 v2 灰度 ≥1000 查询样本）
- 批量路径代号识别：IntentParser 正则须兼容纯代号（如 "GB/T"、"ISO"，无数字后缀）
- L1 只处理国内精准；L2/L3 兜底链保留语义化 fallback（`_DEFAULT_FALLBACK_CHAIN` 等）

## 实施状态

- 阶段一：能力模型 + gongbiaoku 验证原型 ✅
- 阶段二：三级漏斗引擎替代 scorer.py ✅（6 大核心用例符合预期）
- 阶段三：灰度集成（进行中）
- 阶段四：数据闭环回填（query_metrics 样本量当前 0，需补充数据）

## 已识别的修正

- v1.0 失效根因：扁平评分权重无法表达"精准/综合/探索"的分层语义
- 批次 `_get_priority` 收到代号（"GB/T"）而非完整 query 时误判为关键词查询走 L3 → 放宽正则以兼容代号
